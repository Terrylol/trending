# 2026-10-04 追加

## 内容质量与动效（用户 Grill 后重新定方向）

### 拷问结论：原视频不合格
用户问"你觉得这是个合格的功能吗"，我自查后承认不合格：
- 文案全在念屏幕已有的数字（星标/日增/fork），**零信息增量**
- `auto_narrative` 对任何 AI 工具都输出同一句话（关键词猜测的必然结果）
- 7 张卡片布局完全一致，无 demo/截图/代码画面
- 上传功能实际是坏的：`output/cover.png` 从未生成 → B站无封面
- 1分45秒讲5个项目每项目19秒，每15秒没有值得听的内容

### 用户决策
- 定位：**它是内容**，观众**看完就走**
- 质量标准反转：不是"讲得深"，而是**每 15 秒给一个观众听榜单听不到的点**
- 文案：**Agent 轻量探索**（读 README 前 2000 字 + topics），不做深度研究
- 动效：保守档 —— 淡入 + 微缩放 + 转场淡化
- 时长：总时长约 3 分钟
- 上传暂不动

### 本次实现
- 重新写 5 个项目的文案，每条都回答"它是干什么的"而非念数字
- `video_composer._animate()`：FadeIn 0.4s + ZOOM 1.025 + cropped 裁回 + FadeOut 0.25s
- `_validate_video()` 加分辨率断言（缩放不改尺寸的回归防线）
- `write_videofile` 显式 `ffmpeg_params=['-pix_fmt','yuv420p']`
- 新增 `video.animate` 配置开关
- 测试从 35 增到 41，覆盖动效三种场景的尺寸/时长/真实渲染

### MoviePy 踩坑（详见 MEMORY.md）
- `resized(lambda t: X)` 的 t 是**时间**不是倍率 → 两次 resized 裁回会算出尺寸 0
  正确写法：`resized(...).cropped(...)`
- 缩放后必须裁回，否则 1920→1967
- 缩放会让 MoviePy 推断 yuv444p，B站兼容性差，必须锁 yuv420p

### 成品
`output/trending_video.mp4` — 1920×1080 / yuv420p / 24fps / 2分50秒 / 15.1MB
每项目口播 30-33 秒，渲染耗时从 1 分钟涨到 6 分钟（动效逐帧缩放的代价）
